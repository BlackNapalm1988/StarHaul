# Project Structure

StarHaul is a static browser game. The source tree keeps runtime code, tests, generated output, and documentation separate.

## Runtime source

- `index.html`, `style.css`, `main.js`, and `bg.js` are the browser entry points.
- `core/` contains shared engine helpers, config, assets, input, loop, pooling, and save logic.
- `entities/` contains constructors for player and NPC objects.
- `systems/` contains gameplay systems such as contracts, economy, and rescue handling.
- `ui/` contains HUD, docking, map, music, debug, and toast UI modules.
- `world/` contains world generation and simulation/rendering logic.
- `assets/` contains files loaded by the browser at runtime. Keep editor projects, source files, caches, and unused exports out of this folder.
- `reports/` stores local playtest report output generated by `npm start`.

## Tests

All tests live under `tests/` and mirror the runtime folders where useful:

- `tests/core/`
- `tests/systems/`
- `tests/ui/`
- `tests/world/`

Use `npm test` to run the full suite.

## Generated and local-only files

- `dist/` is generated by `npm run build` and is ignored.
- `node_modules/` is generated by `npm ci` or `npm install` and is ignored.
- `.DS_Store` and other OS cache files should not be committed.

## Static build

`scripts/build-static.js` copies only deployable runtime files into `dist/`. It skips test files, `.DS_Store`, and editor project files such as `.pxd`.

## Playtest reporting

`npm start` runs `scripts/playtest-server.js`, which serves the static game and accepts `POST /playtest-report`. The browser report panel opens with `Cmd+\`` or `Ctrl+\`` and appends each submitted report as JSON Lines in `reports/playtest-reports.jsonl`.

## Debug menu

The debug menu opens with plain `` ` ``. It owns playtest toggles for invincibility, gravity arrows, God Mode, entity naming, bounding boxes, and the FPS readout. Keep production-facing Settings separate from debug-only controls.
